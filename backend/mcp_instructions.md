gen-workplace là nơi các agent ngoài phát lệnh chỉ huy vào Phòng giao ban để đội agy CLI làm việc.
BẮT BUỘC cho mọi agent dùng gen-workplace: ghi công việc lên app để Boss theo dõi được trong chatroom và Kanban.
1. Mỗi việc = 1 phiên: trước khi làm, gọi list_conversations. Nếu đã có phiên "VIEC-<n>: <tên việc>" thì dùng lại conv_id đó. Nếu chưa có thì create_conversation(title="VIEC-<n>: <tên việc>", reuse_existing=true).
2. Chia bước thành task Kanban: create_kanban_task(conv_id=<phiên>, viec_ref="VIEC-<n>" (bắt buộc), title, checklist). Gọi claim_task trước khi làm, và update_task_checklist mỗi khi xong một mục.
3. Ghi tiến độ vào chatroom của phiên: log_session_message(conv_id, content, author) ở mỗi mốc (bắt đầu, giao việc, kết quả, bị chặn, xong). Mỗi tin ngắn, kèm link Issue/PR/commit. Tool này chỉ lưu tin, không gọi AI. Đừng dùng gen_chat để ghi log vì gen_chat sẽ gọi agy trả lời.
4. Giao việc cho agy: post_warroom_message với @<vai> (@backend, @devops, @qa, @lead; @security và @frontend đã bỏ, việc giao diện giao cho @backend). Tin war-room mặc định là chế độ THỰC THI (Làm, không --mode plan): nếu tin nêu TSK-n hoặc VIEC-n của task có thật thì giao task đó (assign_task_to_role mode=build), nếu không thì agy chạy trong worktree của vai. Thêm [đọc] ngay sau @vai (vd '@qa [đọc] xem file X') hoặc truyền mode='review' để dùng chế độ Rà soát (agy --mode plan, chỉ đọc). Sau khi dispatch, gọi wait_worker_result(dispatch_id) để chờ kết quả. Ghi kết quả vào phiên (mục 3). Việc cần SỬA CODE qua task Kanban: tool assign_task(task_id, session_id, mode="build") (mặc định là build = "Làm"; cùng hàm với REST POST /api/task/assign), trả dispatch_id, branch, worktree_dir rồi wait_worker_result(dispatch_id) để chờ: agy sửa code với toàn quyền trên máy Fedora trong worktree riêng ../gw-worktrees/TSK-n (nhánh wt/TSK-n từ origin/main), app tự chạy py_compile + toàn bộ test, push nhánh wt/TSK-n và ghi nhánh, commit SHA, kết quả test, link compare vào dispatch và phiên. App không tạo PR (trừ PR nháp khi có GITHUB_TOKEN) và không merge: agent điều phối tạo PR head wt/TSK-n, review (đọc diff + chạy test), rồi mới merge. mode="review" = chỉ đọc như [đọc] trong war-room. assign_task lỗi thì trả isError kèm code + http_status: 404 không có task, 409 task đã done / worker khác đang giữ / đang có lần Làm chạy, 400 thiếu / sai tham số.
5. Đóng việc: complete_task với evidence thật: commit SHA (commit trên nhánh wt/TSK-n của lần Làm cũng được nhận; sau khi merge thì dùng SHA merge), URL PR có thật, dispatch:<id>, hoặc file trong ~/gw-reports/. Không có bằng chứng thì chưa được đóng. Task done thì app tự gỡ worktree của task (giữ nhánh).
6. Quy trình đầy đủ nằm trong skill: repo Genesis-ryan-84-0567536339/Brain → skills/work-style/subskills/gen-workplace-dispatch/SKILL.md.
7. Xác thực: gọi HTTP /mcp phải kèm header Authorization: Bearer <token> (app đang bắt buộc token; thiếu token → 401). Agent điều phối dùng tool qua connector Gen-hub mcp-06594 (đã gửi token), hoặc REST /api/* không cần token: POST /api/gen/conversations/log (ghi log), POST /api/task/assign (giao task, như tool assign_task), POST /api/dispatch/wait (chờ kết quả). Không curl /mcp không token.
